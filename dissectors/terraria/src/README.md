# terraria-wireshark-dissector

Lua dissector for the Terraria multiplayer protocol in Wireshark.

It targets **Terraria 1.4.5.8** (network release 326, handshake string `Terraria326`) only.
Layouts differ even between 1.4.5.x patches, so captures from other releases decode partly:
1.4.5.6 (`Terraria319`) traffic, for instance, fails on packets 7, 22, 27, 29 and 39.

## What it does

- decodes Terraria packets into a Wireshark tree;
- splits packet parsing into one small decoder per message id;
- supports runtime validation on captured traffic.

## Install

```sh
make install
```

This writes a small loader, `terraria.lua`, into `~/.local/lib/wireshark/plugins` (override with
`PLUGIN_DIR=...`). Wireshark runs every `.lua` file under its plugin folder, so the modules are
kept out of it: by default the loader runs them straight from this checkout's `src/`, and
`make install MODULE_DIR=/some/dir` copies `src/` there instead. An older install that linked
`src/terraria/` into the plugin folder is cleaned up on the next `make install`.

## Check

```sh
make check-lua
```

## Tests

Each `tests/fixtures/*.txt` is a text2pcap hex dump (the release-326 ones are generated by
`tests/build_fixtures.py`); the test dissects it with the plugin from
`src/` (an installed copy is ignored) and compares the Info column and the Terraria tree with
`*.expected`. Needs `tshark` and `text2pcap`.

```sh
make test
make test-update   # rewrite *.expected after an intended change
```

## Runtime check

Run the dissector against a capture:

```sh
make runtime-check PCAP=test_data/terraria.pcap
```

## Project layout

```text
plugin/terraria.lua.in      loader that make install puts in the plugin folder
src/
├── terraria.lua            entry point: registers the protocol on tcp.port 7777
└── terraria/
    ├── dissector.lua       TCP framing, routing, Info column
    ├── context.lua         the 3-byte frame header
    ├── fields.lua          header fields, experts, registration list
    ├── game/               game knowledge: packet catalog, tile properties
    └── payload/
        ├── dissector.lua   runs a payload's decoder and reports what is left over
        ├── registry.lua    message id -> decoder
        ├── fields.lua      every decoder field
        ├── builders/       one decoder per message id, named after vanilla MessageID;
        │                   init.lua lists them all in id order
        ├── structures/     layouts shared by several packets
        ├── reader/         PayloadReader, the read-and-show API every decoder uses
        └── wire/           byte cursor, strings, NetworkText
```

Each decoder's display-filter fields are named after its file, which is the vanilla message name
in snake_case: `payload/builders/sync_npc.lua` (SyncNPC, 23) declares `terraria.sync_npc.*`.
Header fields are `terraria.length`, `terraria.id` and `terraria.payload`. `make test` also
compares the full field list with `tests/fields.expected`, so a renamed filter shows up in review.

A decoder reads its payload only through `PayloadReader`: each method consumes bytes, adds one
tree item for them and returns the value, so conditional fields branch on what was just read.
`PayloadReader.reader` and `.tree` are private; LuaLS (`make check-lua`) flags direct use.

## Packet reference

There is no official description of the 1.4.5 protocol. Message ids, names and layouts follow
[terrustia](https://github.com/bybrooklyn/terrustia) (`docs/packet-ids.tsv`,
`docs/protocol-notes.md` and the `terrustia-proto` crate), a 1.4.5.8 server transcribed from the
decompiled game. Packets whose layout terrustia does not describe are shown as raw bytes:
141 RequestLucyPopup, 142 SyncProjectileTrackers, 145, 148, 150 SpectatePlayer, 152 ItemUseSound,
158 ExtraSpawnSectionLoaded, 161 HostToken, and 93 SocialHandshake and 94 DevCommands. Packets terrustia relays without parsing keep
their older layouts.
